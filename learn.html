How QR codes work

A QR code is a 2D black-and-white grid that encodes data and protects it with mathematical redundancy. This page walks through every part — what it is, why it's there, and how a scanner reads it. Want to see one live? Open the scanner →

1. The grid

A QR code is built on a square grid of black and white squares called modules. The grid size is set by the QR version (1 through 40). Each version up adds 4 modules per side:

  • Version 1 → 21×21 modules
  • Version 2 → 25×25 modules
  • Version 10 → 57×57 modules
  • Version 40 → 177×177 modules (the largest)

The more data you encode, the higher the version needed.

2. Function patterns

Some modules don't carry data — they exist purely to help scanners find and orient the code.

Finder patterns

Three identical 7×7 nested squares in three of the four corners. The ratio of dark:light:dark:light:dark widths through any line through the center is always 1:1:3:1:1. This pattern is mathematically distinctive — even at angles and partial occlusion, scanners can detect it reliably.

Three corners, not four — the missing fourth corner tells the scanner which way is up.

Separators

A 1-module-wide white border on the inside edges of each finder pattern. Without these, dark data modules next to the finder could fool the ratio detector.

Timing patterns

Two strips of alternating dark/light modules running across row 6 and column 6 (between the finder patterns). The scanner uses them as a ruler — counting the alternations tells it how many modules wide the code is, which tells it the version. The timing pattern also anchors the grid when the image is warped or photographed at an angle.

Alignment patterns

Starting at version 2, smaller 5×5 nested squares appear at predictable positions. Their job is to correct for local distortion — when the QR is photographed at an angle, printed on a curved surface, or warped by the camera lens. With multiple alignment patterns, the scanner can compute a non-linear correction map.

Bigger QR codes need more alignment patterns:

  • V1: zero alignment patterns
  • V2–V6: one alignment pattern
  • V7–V13: six alignment patterns
  • V40: 46 alignment patterns

3. Format information

Two copies of 15 bits encoding two facts the scanner must know before reading anything else:

  1. The error correction level (L, M, Q, or H)
  2. The mask pattern used (0 through 7)

Why two copies? So that even if part of the format strip is damaged, the scanner can still recover it. The 15 bits are BCH-encoded (10 bits of redundancy on 5 bits of real info) and XORed with 0x5412 to avoid an all-zero pattern, which would be visually ambiguous.

Error correction levels

QR codes use Reed-Solomon error correction. You pick a level when you generate the code:

  • L — recovers ~7% damaged codewords. Smallest QR, least durable.
  • M — ~15% recovery. Common default.
  • Q — ~25% recovery.
  • H — ~30% recovery. Largest QR, most durable. Lets you cover ~30% of the code with a logo and still scan.

Mask patterns

After the data + error correction modules are placed, one of eight mask patterns is XORed onto them. The goal: avoid large runs of dark or light modules, avoid accidentally forming finder-pattern-like ratios in the data, and balance overall darkness. A QR generator tries all 8 masks, scores them with a penalty function, and picks the best.

The 8 masks (a module at row, col is flipped when the formula is true):

  • Mask 0: (row + col) mod 2 == 0
  • Mask 1: row mod 2 == 0
  • Mask 2: col mod 3 == 0
  • Mask 3: (row + col) mod 3 == 0
  • Mask 4: (⌊row/2⌋ + ⌊col/3⌋) mod 2 == 0
  • Mask 5: (row · col) mod 2 + (row · col) mod 3 == 0
  • Mask 6: ((row · col) mod 2 + (row · col) mod 3) mod 2 == 0
  • Mask 7: ((row + col) mod 2 + (row · col) mod 3) mod 2 == 0

4. Version information (V7+)

Versions 1–6 are recognizable by counting modules along the timing pattern. Versions 7 and above also include an explicit version block — two 6×3 patches, one near the top-right finder, one near the bottom-left. Each carries 18 bits (6 bits of version number + 12 bits of BCH redundancy).

5. The dark module

A single module that's always dark, regardless of content. Located at row (4 × version + 9), column 8. It's just above the bottom-left finder pattern's separator. The spec quirkily requires it; treat it as a sanity-check landmark.

6. Data + error correction

Everything else — every module that isn't a finder, separator, timing, alignment, format, version, or dark module — is either a data codeword or an error-correction codeword.

Placement order

Codewords are placed starting from the bottom-right corner, working up and down in 2-column-wide vertical channels, snaking back and forth, skipping over function patterns. Inside each 2-column channel, bits are placed right-bit-first, then left-bit, then up to the next row.

Encoding modes

The 4-bit mode indicator at the start of the data tells the scanner how to interpret the bits that follow:

  • Numeric (digits 0–9) — 10 bits per 3 digits. Most compact.
  • Alphanumeric (0–9, A–Z, space, $%*+-./:) — 11 bits per 2 characters.
  • Byte (arbitrary bytes, usually ISO-8859-1 or UTF-8) — 8 bits per byte. Used for URLs, anything non-ASCII.
  • Kanji (Shift-JIS Japanese) — 13 bits per character.

A single QR code can mix multiple modes — switching with a new 4-bit mode indicator and length count any time.

Reed-Solomon error correction

The data codewords are followed by Reed-Solomon parity codewords. RS works over the Galois field GF(2^8), treating each byte as an element. The number of parity bytes depends on the error correction level. RS can correct any combination of e errors and s erasures (known-missing bytes) such that 2e + s ≤ number of parity bytes.

For larger QR codes, the codewords are split into multiple blocks, each with its own parity. This prevents a single concentrated smudge from wiping out enough data in one block to be unrecoverable — the damage spreads across blocks, each of which can heal independently.

7. The quiet zone

The specification calls for a 4-module-wide white margin around the code. This isn't decoration — many scanners fail or struggle without it. If you're designing a QR code into print or a UI, leave the margin.

The decoding sequence in order

  1. Find three finder patterns by scanning rows/columns for the 1:1:3:1:1 ratio.
  2. Determine rough orientation from the three positions.
  3. Count modules along the timing pattern → determine version (or read version info for V7+).
  4. Locate alignment patterns; compute a corrective grid sampling map.
  5. Read each format-info copy; majority vote or BCH-correct to get EC level + mask.
  6. XOR the mask off the data + ECC modules.
  7. Read codewords in the standard zigzag order.
  8. De-interleave codeword blocks; run Reed-Solomon correction on each.
  9. Parse the bitstream: mode → length → content → optional more modes → terminator.
